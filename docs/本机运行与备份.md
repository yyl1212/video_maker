# 本机运行、停止、备份与恢复

本平台单机、单用户，每个数据目录只运行一个后端实例。模型服务由用户独立启动；平台不检测内存、不卸载或恢复模型，也没有云端回退。

## 1. 准备环境

已验证运行目标：Python 3.13、Node.js 24、uv、FFmpeg/ffprobe。FFmpeg需要libx264、AAC及scale的reset_sar支持；以启动预检结果为准。

在仓库根目录首次准备：

```bash
cp .env.example .env
(cd backend && uv sync --locked)
(cd frontend && npm ci)
```

模型连接在页面保存到数据库，不写入前端构建。当前已验证：

- 文本：本机OpenAI兼容服务，默认`http://127.0.0.1:1234/v1`；已实测`qwen3.8-27b-mlx@8bit`。空正文的reasoning_content兼容仅限该精确ID与旧已验证别名，其他模型需要正常正文JSON。
- 图片：Draw Things本机gRPC，默认7859、TLS开启；`flux_2_klein_9b_kv_i8x.ckpt`，最多8张有序参考，宽高为64倍数。
- 音画：本机MLX-Serve，默认11234；`ddalcu/MiniMax-H3-FL2VA-MLX-Serve-8bit`。目标1～8秒，quality20步或fast4步，尺寸32倍数、短边≤384、长边≤672。

在各连接面板检查服务、选择模型并保存。连接检查不生成内容，也不能证明上游当前空闲。模型文件由用户预先安装，平台不自动下载。

## 2. 一条命令启动生产工作台

```bash
./scripts/start-local.sh --check
./scripts/start-local.sh --build
```

`--check`仅检查环境、配置和8000/3000端口，不创建数据库、不请求模型。`--build`在540秒总截止内构建前端后启动；已有生产构建时，直接运行：

```bash
./scripts/start-local.sh
```

打开[本机工作台](http://127.0.0.1:3000)。脚本读取仓库根目录`.env`，但不会把配置当作shell执行。环境变量优先于.env；相对VM_DATA_DIR以仓库根目录为基准，保存为绝对路径。路径包含空格时在.env中使用引号。

脚本固定后端8000和前端3000；端口已占用会退出，不终止占用者。VM_BACKEND_URL需为本机HTTP的8000端口；VM_FRONTEND_ORIGINS须包含`http://127.0.0.1:3000`。自定义其他端口请按README手动分别启动，并在改变VM_BACKEND_URL后重新构建前端，避免使用旧rewrite地址。

运行时使用生产构建、一个后端进程，不开`--reload`、多worker或热重载。生成中可以编辑和浏览，任务仍使用提交时的冻结快照。忙时拒绝新任务，不排队。

## 3. 停止与失败恢复

在启动终端按Ctrl+C。脚本先通知本次启动的前后端退出，后端最多先等待15秒完成HTTP后台工作，再按任务引擎规则取消和收尾；脚本等待30秒后仅强停本次拥有的残留进程组。模型服务保持独立，不随工作台关闭。

应用中断时不会自动重发任务。下次启动会标记遗留任务失败；能证明本地进程和上游已结束时释放执行槽。若显示`NEEDS_RESET`，先手工停止或重启任务条指明的模型服务，确认旧请求已停止，再使用页面恢复按钮。刷新页面或仅测试连接不会自动解锁。

提交响应丢失时，使用“查询或重试原提交”，复用原幂等键和快照。文本结果仍需明确采纳，媒体结果仍需明确采用。

## 4. 数据目录内容

以实际VM_DATA_DIR为准，默认仓库根目录`data/`：

| 内容 | 用途 |
|---|---|
| app.sqlite3及可能存在的-wal/-shm | 项目、角色、剧集、分镜、选择、任务、模型连接设置 |
| media/ | 不可变图片、视频、成片及缩略图 |
| task-inputs/ | 按任务冻结的参考、首帧、片段 |
| jobs/ | 任务执行记录、成片manifest.json及受管进程身份 |
| staging/、quarantine/ | 临时文件及未登记孤立文件隔离 |
| .workspace.lock | 操作系统工作区锁文件，存在不代表仍被占用 |

不要在应用运行时删除锁文件、改资产原文件或只复制SQLite主文件。文件发布后数据库提交失败的孤立结果由启动巡检隔离，不会自动登记为成功。

## 5. 停机备份

1. 停止本工作台，确认本次前后端已经退出，且没有另一实例使用该数据目录。
2. 将整个数据目录复制到独立备份位置，包括可能存在的SQLite日志、所有媒体、冻结输入及任务清单；不要筛选只复制当前选中的资产。
3. 另存`.env`、对应Git提交号、Python/Node/FFmpeg版本和模型ID。模型权重由各本机模型应用独立管理，不在本平台数据目录内。
4. 核验备份中的SQLite完整性，并保留校验结果。以下示例只读检查备份，不启动平台：

```bash
./backend/.venv/bin/python - '/绝对路径/备份/app.sqlite3' <<'PY'
import sqlite3, sys
from pathlib import Path
path = Path(sys.argv[1]).resolve()
with sqlite3.connect(path.as_uri() + '?mode=ro', uri=True) as connection:
    assert connection.execute('PRAGMA integrity_check').fetchall() == [('ok',)]
    assert connection.execute('PRAGMA foreign_key_check').fetchall() == []
print('SQLite完整性及外键检查通过')
PY
```

备份可能包含剧本和本地文件路径，请保存在自己控制的位置。本期没有物理清理功能，归档/软删除的历史仍应随备份保存。

## 6. 恢复到原绝对路径

数据库与任务快照保存媒体的绝对路径。首版恢复要求回到原VM_DATA_DIR绝对路径：

1. 停止工作台，将当前目录另存为独立回退备份。
2. 将备份完整复制回原绝对路径；不要直接从备份副本目录启动应用。
3. 恢复对应版本代码和配置，运行`--check`，再启动并检查项目、素材预览和历史成片清单。
4. 若工作区保留执行未知状态，按页面指引确认上游停止后恢复，不直接修改数据库状态。

仅改VM_DATA_DIR或搬文件夹不会重写数据库中的绝对路径。异机用户名、挂载点或数据根路径不同，需要单独的路径迁移方案；本版不提供跨路径恢复或旧DrawThings数据导入。

## 7. 回归与验收命令

从仓库根目录分组执行，每个命令有540秒总截止：

```bash
python3 scripts/run-check.py --cwd backend -- uv run pytest -q
python3 scripts/run-check.py --cwd frontend -- npm test
python3 scripts/run-check.py --cwd frontend -- npm run typecheck
python3 scripts/run-check.py --cwd frontend -- npm run lint
python3 scripts/run-check.py --cwd frontend -- npm run build
(cd frontend && npx playwright install chromium)
python3 scripts/run-check.py --cwd frontend -- npm run test:e2e
```

浏览器回归需要8000/3000空闲，配置禁止复用已有服务，每轮创建独立临时数据目录，只替换模型推理，仍使用真实生产页面、业务API、SQLite、磁盘和FFmpeg。自动媒体播放为静音播放进度验证，有声音轨由媒体探测与PCM测试核验。完整真实模型验收单独逐项执行，不将整条链路塞进一个超过10分钟的命令。
